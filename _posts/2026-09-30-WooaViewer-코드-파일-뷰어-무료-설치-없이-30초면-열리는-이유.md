## 기능 상세: 실제로 써본 5가지

### 1. 문법 강조와 줄 번호

가장 먼저 체감되는 부분이다. 키워드, 문자열, 주석, 숫자가 서로 다른 색으로 표시되고 줄 번호가 왼쪽에 붙는다. 오류 로그에서 "12번째 줄"이라는 안내를 받았을 때 바로 찾아갈 수 있어서 편했다.

### 2. 확장자 자동 인식

파일을 올리면 확장자를 보고 언어를 알아서 판단한다. `.py`는 파이썬, `.html`은 마크업, `.json`은 데이터 구조로 잡아준다. 인식이 안 되는 경우에는 언어를 직접 고를 수 있다.

### 3. 드래그 앤 드롭 업로드

파일 선택 버튼을 눌러 탐색기를 여는 방식과, 화면에 끌어다 놓는 방식 둘 다 된다. 여러 개를 한 번에 올리는 것도 가능해서 로그 파일 여러 개를 비교할 때 유용했다.

### 4. 검색과 줄 이동

긴 파일에서 특정 변수명을 찾을 때 브라우저 기본 검색(Ctrl+F)이 그대로 먹힌다. 별도 검색창을 배울 필요가 없다는 게 오히려 장점이었다.

### 5. 복사와 다운로드

읽기만 하는 뷰어지만 내용을 복사하거나 다른 이름으로 저장하는 것도 가능하다. 확인 후 원본을 그대로 두고 싶을 때 쓴다.

## 실제 사용 후기: 30초 안에 끝난 순서

태블릿에서 진행한 실제 순서는 이렇다.

1. 브라우저 주소창에 주소 입력 (약 3초)
2. 파일 탐색기에서 `.js` 파일을 화면 위로 끌어다 놓기 (약 5초)
3. 렌더링 완료 대기 (파일 크기에 따라 1~3초)
4. Ctrl+F로 확인하려던 함수명 검색 (약 10초)

체감상 파일을 놓고 결과가 뜨기까지 2초 내외였다. 200줄 정도의 파일 기준이고, 수천 줄짜리 파일은 조금 더 걸리지만 기다릴 만한 수준이었다. 설치형 편집기를 켜는 부팅 시간과 비교하면 차이가 확실했다.

아쉬운 점도 있었다. 코드를 편집하거나 저장하는 기능은 없다. 애초에 뷰어이기 때문에 "읽고 확인한다"는 목적 밖으로는 나가지 않는다. 대용량 파일을 여러 개 동시에 열면 브라우저 탭이 무거워지는 것도 감안해야 한다.
