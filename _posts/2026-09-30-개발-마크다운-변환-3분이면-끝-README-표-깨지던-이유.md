## 개발 마크다운 변환, 왜 매번 손이 멈출까

개발 마크다운 변환 작업은 사소해 보이지만 README 하나 정리하다 30분을 날리는 경우가 많다. 로컬 에디터를 켜고, 패키지를 설치하고, 미리보기 창을 띄우는 순간 이미 흐름이 끊긴다. 문제는 대부분 문법이 아니라 "어디서 확인하느냐"다. 코드 리뷰 중에, 배포 직전에, 위키에 붙여넣기 직전에 서식이 무너지는 걸 발견하기 때문이다.

## 주요 기능 상세

### 1. 실시간 미리보기

입력하는 즉시 렌더링 결과가 갱신된다. 표 정렬, 인용문, 중첩 리스트처럼 눈으로 확인해야 하는 요소를 별도 빌드 없이 검증할 수 있다. README 커밋 전 최종 점검용으로 쓰기 좋다.

### 2. HTML·일반 텍스트 양방향 변환

마크다운을 HTML로, 혹은 반대 방향으로 옮길 때 태그가 그대로 노출되는 문제를 잡아준다. `<br>` 같은 인라인 태그가 코드블록 안에 섞여 들어가는 흔한 사고를 미리 볼 수 있다.

### 3. 코드블록 언어 지정 유지

```js, ```bash 같은 펜스 표기가 렌더링 후에도 유지되는지 확인 가능하다. 언어 하이라이팅이 빠지면 문서 신뢰도가 떨어지는데, 이 부분을 눈으로 잡아낼 수 있다.

### 4. 표·체크박스 확장 문법 대응

GitHub 스타일 체크박스(- [x]), 표 정렬(:---, :---:), 각주까지 한 화면에서 테스트된다. 사내 위키와 GitHub README 문법이 달라 생기는 재작업을 줄여준다.

## 실제 사용 후기

필자는 주로 두 가지 상황에서 쓴다. 첫째, PR 설명을 정리할 때. 로컬 에디터를 켜는 대신 브라우저 탭 하나를 열어두고 붙여넣는다. 표가 깨지는지 즉시 보이기 때문에 커밋 메시지를 다시 쓰는 일이 줄었다.

둘째, 사내 위키로 문서를 옮길 때. 위키마다 지원하는 문법이 조금씩 달라서, 옮기기 전에 렌더링 결과를 먼저 확인한다. 이 과정을 거치면 "왜 여기서만 표가 깨지지"라는 상황이 거의 사라진다.

단점도 있다. 아주 큰 문서(수만 줄)를 붙여넣으면 브라우저가 잠깐 버벅인다. 이 경우 섹션 단위로 나눠서 확인하는 편이 낫다. 또 오프라인에서는 쓸 수 없으니, 비행기 안 같은 환경에서는 로컬 도구를 병행해야 한다.
