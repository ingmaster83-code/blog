## 수동 정리와 자동 압축, 결과가 갈리는 지점

### 사람이 지우면 생기는 대표 실수

가장 흔한 실수는 **공백을 무조건 없애는 것**입니다. `margin: 0 auto`처럼 값 사이 공백이 의미를 갖는 문법에서 공백을 지우면 선언 자체가 무효가 됩니다. 또 하나는 **미디어 쿼리 조건을 건드리는 것**입니다. `@media (max-width: 768px)`에서 괄호 안 공백을 임의로 정리하면 일부 브라우저에서 조건 인식이 흔들립니다.

### 도구가 처리하는 방식

온라인 CSS 압축 도구는 단순 치환이 아니라 CSS 문법 단위로 토큰을 나눈 뒤 안전한 공백과 주석만 제거합니다. 그래서 결과물이 수동 편집보다 길어 보여도 실제로는 깨지지 않는 최소 형태에 가깝습니다. CSS 용량 줄이기의 목적이 로딩 속도 개선이라면, 몇 바이트 더 줄이는 것보다 한 번에 정상 동작하는 편이 이득입니다.

## 주요 기능

### 원본 대비 절감률 확인

압축 전후 크기를 나란히 보여주기 때문에 실제로 얼마나 줄었는지 바로 판단할 수 있습니다. 체감상 10% 미만이면 이미 잘 정리된 파일이고, 30% 이상이면 주석과 중복 선언이 많았다는 신호입니다.

### 결과 미리보기와 복사

압축본을 그대로 복사해 배포용 파일로 쓰거나, 원본과 비교해 어느 부분이 정리됐는지 확인할 수 있습니다. 웹 성능 최적화 작업 중 CSS minify 단계만 따로 떼어 점검할 때 유용합니다.

### 브라우저 안에서만 처리

코드를 붙여넣는 순간부터 결과가 나올 때까지 모든 계산이 로컬에서 끝납니다. 외부 CSS 프레임워크를 커스터마이즈한 파일처럼 외부에 두기 부담스러운 코드도 그대로 넣을 수 있습니다.

## 활용 팁

### 원본은 반드시 따로 보관

압축본은 사람이 읽기 어렵습니다. 디자인 수정이 필요할 때 압축본을 열면 어디를 고쳐야 할지 찾기부터 막힙니다. 원본 → 수정 → 재압축 순서를 습관으로 두는 편이 훨씬 빠릅니다.

### 배포 직전 한 번만

개발 중에는 압축하지 않는 편이 좋습니다. 브라우저 개발자 도구에서 스타일을 추적할 때 압축된 코드는 한 줄로 이어져 있어 디버깅이 어려워집니다. 최종 배포 파일에만 적용하세요.

### 여러 파일을 합칠 때 순서 주의

CSS 파일 여러 개를 하나로 합친 뒤 압축하면 요청 수가 줄어 효과가 큽니다. 다만 로드 순서가 바뀌면 우선순위가 달라지므로, 기존 link 태그 순서를 그대로 유지한 채 합쳐야 합니다.
