## Base64 인코딩 무료 방법, 검색부터 지치셨다면

Base64 인코딩 무료 방법을 찾다가 광고 팝업만 잔뜩 뜨는 사이트에서 헤매본 적 있으실 겁니다. 저도 얼마 전 API 테스트용 토큰을 Base64로 바꿔야 해서 급하게 검색했다가, 회원가입을 요구하거나 결과값을 복사하면 줄바꿈이 깨지는 도구 때문에 20분을 그냥 날렸습니다. 결국 돌아온 곳은 브라우저에서 바로 돌아가는 단순한 웹 도구였고, 그게 바로 [WooaDev 무료로 사용하기](https://wooadev.wooahouse.com)입니다.

이 글에서는 제가 실제로 써보면서 확인한 인코딩·디코딩 순서와, 처음 쓸 때 놓치기 쉬운 주의사항을 정리했습니다.

## WooaDev Base64 도구, 어떤 점이 편했나

### 설치도 로그인도 필요 없음

가장 마음에 들었던 점은 진입 장벽이 거의 없다는 것입니다. 프로그램 설치, 계정 생성, 이메일 인증 같은 단계가 전부 생략됩니다. 문자열을 붙여넣고 버튼 한 번 누르면 끝이라, 인코딩 결과가 필요할 때마다 탭 하나 열어두고 쓰기 좋습니다.

### 인코딩과 디코딩을 한 화면에서

Base64 변환은 방향이 두 가지입니다. 사람이 읽는 텍스트를 Base64 문자열로 바꾸는 인코딩, 반대로 Base64 문자열을 원래 텍스트로 되돌리는 디코딩입니다. 사이트를 옮겨 다니지 않고 같은 화면에서 양방향으로 처리할 수 있어서, 결과를 검증할 때 특히 편합니다.

### 한글·특수문자 처리 확인

Base64는 원래 바이트 단위로 변환하기 때문에 한글이나 이모지가 섞이면 결과가 깨지는 도구가 많습니다. UTF-8 기준으로 처리되는지 확인하려면 "안녕하세요" 같은 문장을 넣고 디코딩까지 왕복 테스트를 해보면 됩니다. 제가 테스트했을 때는 왕복 변환이 정상적으로 돌아왔습니다.

## 사용법 3단계

### 1단계: 변환할 값 붙여넣기

입력창에 인코딩할 텍스트를 넣습니다. JSON 조각, API 키, 이미지의 data URI 문자열 등 형태는 상관없습니다. 긴 문자열도 붙여넣기만 하면 되니 별도 편집이 필요 없습니다.

### 2단계: 인코딩 또는 디코딩 선택

변환 방향을 고르고 실행 버튼을 누릅니다. 디코딩할 때는 입력값이 Base64 형식이어야 하며, 알파벳 대소문자와 숫자, `+`, `/`, `=` 조합으로만 이루어져 있어야 합니다. 중간에 공백이나 줄바꿈이 섞여 있으면 오류가 날 수 있습니다.

### 3단계: 결과 복사 후 원본과 대조

출력된 문자열을 복사해 코드나 문서에 붙여넣습니다. 이때 끝에 붙는 `=` 패딩이 잘렸는지 한 번 확인하세요. 패딩이 빠지면 디코딩 단계에서 실패하는 경우가 있습니다.

## 주의사항

- Base64는 암호화가 아닙니다. 누구나 디코딩할 수 있으므로 비밀번호나 개인키를 이 방식으로 "숨긴다"는 생각은 위험합니다.
- URL에 Base64 값을 넣을 때는 `+`가 공백으로 해석될 수 있어 URL-safe 변형이 필요할 수 있습니다.
- 디코딩 결과가 깨져 보이면 원본이 UTF-8이 아닌 다른 인코딩일 가능성을 의심해보세요.
- 매우 긴 문자열은 브라우저에 따라 처리 속도가 달라질 수 있으니, 결과가 잘렸는지 마지막 부분을 확인하는 습관이 좋습니다.
