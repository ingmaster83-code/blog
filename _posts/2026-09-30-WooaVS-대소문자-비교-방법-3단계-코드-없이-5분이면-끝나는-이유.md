## 대소문자 하나 때문에 데이터가 어긋나는 순간

WooaVS 대소문자 비교 방법을 찾는 사람은 대부분 비슷한 상황을 겪는다. 엑셀에서 회원 ID 목록을 정리했는데 VLOOKUP이 계속 오류를 뿜거나, API 응답 값과 DB 값이 눈으로는 똑같아 보이는데 조건문이 false를 반환하는 경우다. 원인은 단 하나, `User01`과 `user01`을 같은 값으로 착각한 것이다.

사람 눈에는 같아 보여도 컴퓨터는 이 둘을 완전히 다른 문자열로 취급한다. 문제는 이 차이를 육안으로 찾아내는 게 거의 불가능하다는 점이다. 1000줄짜리 로그에서 대문자 하나가 섞여 있는지 확인하려면 하루가 걸린다.

## 원인은 인코딩이 아니라 비교 규칙

대소문자 비교가 어긋나는 이유는 크게 세 가지다.

첫째, 데이터마다 다른 대소문자 규칙을 적용하기 때문이다. 어떤 시스템은 이메일을 소문자로 저장하고, 어떤 시스템은 입력값 그대로 보관한다.

둘째, 유니코드 정규화 차이다. 겉보기엔 같은 알파벳이지만 결합 문자로 저장된 경우 바이트 값이 달라진다.

셋째, 한글 자모 분리 현상이다. `한글`을 `ㅎㅏㄴㄱㅡㄹ`로 입력한 값과 완성형 `한글`은 코드 포인트가 완전히 다르다. 이런 케이스까지 잡으려면 단순 diff 도구로는 부족하다.

이럴 때 쓰는 게 [WooaVS 무료로 사용하기](https://vskit.wooahouse.com)다. 설치도, 회원가입도, 코드 작성도 필요 없다. 텍스트 두 개를 붙여넣고 옵션만 켜면 끝난다.

### 1단계: 비교할 텍스트 입력

페이지에 들어가면 두 개의 입력 영역이 나온다. 왼쪽에 원본, 오른쪽에 비교 대상을 붙여넣는다. 표 형태 데이터, JSON, 로그 파일 무엇이든 상관없다.

### 2단계: 옵션 설정

대소문자 구분, 공백 무시, 줄바꿈 처리 옵션 중 필요한 것을 체크한다. 대소문자 비교가 목적이라면 반드시 "대소문자 구분" 항목을 활성화해야 한다. 이 옵션을 켜지 않으면 `Apple`과 `apple`이 동일한 값으로 처리되므로 주의하자.

### 3단계: 결과 확인

비교 버튼을 누르면 다른 부분이 하이라이트로 표시된다. 대소문자만 다른 구간, 공백 개수가 다른 구간, 아예 존재하지 않는 라인이 색상으로 구분되므로 어디를 수정해야 하는지 즉시 파악된다.

### 4단계: 결과 복사 및 재검증

수정한 텍스트를 다시 붙여넣어 재비교한다. 반복 검증까지 포함해도 5분이면 충분하다.
