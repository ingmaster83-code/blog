## 실제로 확인할 수 있는 것들

### 기본 구조 검사
여는 태그와 닫는 태그가 짝을 이루는지, div 중첩이 꼬이지 않았는지 확인하는 게 첫 단계입니다. 코드가 길어질수록 눈으로는 못 잡습니다. 미리보기 화면이 비어 있거나 일부만 나온다면 십중팔구 태그 닫힘이 빠진 겁니다.

### 실시간 미리보기
수정할 때마다 화면이 즉시 갱신됩니다. CSS 한 줄 바꾸고 다시 새로고침하는 번거로움이 없습니다. 모바일 화면 폭을 가정해서 확인할 때도 편합니다.

### 외부 리소스 로딩 확인
이미지 경로, script 위치, 링크 태그가 제대로 물려 있는지도 이 단계에서 드러납니다. 코드 자체는 멀쩡한데 화면이 안 나오는 경우, 대개 경로 문제입니다.

## 붙여넣기 전에 확인해야 할 3가지

- **닫힘 태그 누락**: `<div>`만 열고 닫지 않은 채 다음 섹션으로 넘어가는 실수가 가장 흔합니다.
- **속성 따옴표 불일치**: `class="btn'` 같은 짝 안 맞는 따옴표는 검사 도구가 잡아주지 못하는 경우도 있습니다.
- **script 태그 위치**: head 안에 넣으면 DOM 로딩 전에 실행되어 미리보기가 깨지는 경우가 많습니다.

## 솔직한 사용 후기

장점은 확실합니다. 무겁지 않고, 광고가 화면을 덮지 않고, 미리보기 반응이 빠릅니다. 복잡한 코드 에디터를 켜기 애매한 상황, 예를 들어 메일 본문용 HTML을 잠깐 검사할 때 특히 유용했습니다.

아쉬운 점도 있습니다. 코드 자동 완성이나 문법 오류를 정밀하게 짚어주는 린트 기능은 기대하기 어렵습니다. 그래서 저는 WooaDev에서 1차 구조 확인 → 미리보기로 렌더링 확인 → 실제 배포 전 브라우저 개발자 도구로 2차 검증, 이 순서로 씁니다. 무료 도구 하나로 모든 걸 해결하려는 생각 자체가 함정입니다.
