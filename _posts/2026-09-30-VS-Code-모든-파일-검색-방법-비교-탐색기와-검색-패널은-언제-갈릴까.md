## 왜 매번 파일을 못 찾고 헤매는 걸까

vs code 모든 파일 검색 방법을 검색하는 사람 대부분은 비슷한 상황에 놓여 있다. 퇴근 30분 전, 팀장이 "지난 분기 리포트에 있던 그 문구 어디 갔죠?"라고 묻는다. 프로젝트 폴더는 수백 개 파일로 얽혀 있고, 언제 만든 건지 기억도 안 나는 `report_final_v3.md`가 어딘가에 숨어 있을 뿐이다. 탐색기 트리를 위아래로 훑어도 답이 안 나온다.

문제는 도구가 없어서가 아니다. VS Code에는 이미 강력한 검색 수단이 두 가지 들어 있다. 다만 **언제 어느 쪽을 써야 하는지**를 구분하지 않아서 매번 헛손질을 하는 것이다. 이 글은 그 갈림길을 정리한다.

## 두 가지 검색 방식, 뭐가 다른가

VS Code의 검색은 크게 두 갈래다. 하나는 사이드바의 탐색기(Explorer), 다른 하나는 검색 패널(Search)이다. 이름은 비슷해 보이지만 접근 방식이 완전히 다르다.

### 탐색기 — 파일 이름과 위치를 좇는 방식

탐색기는 **파일 자체**를 찾는다. 파일명을 알고 있거나, 폴더 구조를 어느 정도 기억할 때 강하다. `Ctrl+P`(맥은 `Cmd+P`)로 여는 퀵 오픈(Quick Open)이 대표적이다. 파일명 일부만 입력해도 후보가 실시간으로 좁혀진다.

### 검색 패널 — 파일 안의 내용을 파고드는 방식

반대로 검색 패널은 **파일 속 텍스트**를 찾는다. `Ctrl+Shift+F`로 열리며, 프로젝트 전체에서 특정 단어·문자열이 들어간 위치를 전부 긁어낸다. "이 함수 이름이 어느 파일에서 쓰였는지" 같은 질문에 답하는 건 이쪽이다.

## 실제 업무에서 갈리는 지점

직장인이나 학생이 자주 겪는 장면으로 나눠 보면 차이가 선명해진다.

### 과제 제출 전, 참고문헌 목록을 찾을 때

보고서 파일 이름이 기억나지 않으면 탐색기다. `Ctrl+P`를 누르고 "참고" 두 글자만 쳐도 관련 파일이 쏟아진다. 반면 파일명은 아는데 그 안에 "2025년 개정"이라는 문구가 들어간 파일만 골라야 한다면 검색 패널이 맞다.

### 협업 코드에서 변수명을 일괄 확인할 때

팀 프로젝트에서 `userIdx`를 `userId`로 바꾸기 전, 어디서 쓰이는지 전부 봐야 한다. 이때 검색 패널의 결과 목록은 파일별로 그룹화되어 나오고, 각 줄을 클릭하면 해당 위치로 바로 이동한다. 탐색기로는 절대 할 수 없는 작업이다.

## 결과가 너무 많을 때 줄이는 팁

검색 패널을 쓰다 보면 `node_modules`, `dist`, `.git` 같은 폴더 때문에 결과가 수천 건으로 불어난다. 이럴 때 검색창 아래 **포함/제외 필터**를 쓰면 된다. 제외 칸에 `node_modules, dist`만 넣어도 체감 속도가 몇 배는 달라진다.

### 단축키 조합 정리

- `Ctrl+P` — 파일명으로 빠르게 이동
- `Ctrl+Shift+F` — 프로젝트 전체 내용 검색
- `Ctrl+Shift+E` — 탐색기 패널로 즉시 전환
- `F4` — 검색 결과 다음 항목으로 점프

이 네 개만 손에 익어도 "파일이 어디 갔지" 하는 5분짜리 헛수고가 거의 사라진다.
