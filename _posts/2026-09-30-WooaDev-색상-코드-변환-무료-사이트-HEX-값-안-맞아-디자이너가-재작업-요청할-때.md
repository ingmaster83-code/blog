## 색상 코드 변환 무료 사이트가 필요한 순간

디자인 시안에 적힌 HEX 값을 그대로 CSS에 넣었는데 화면에서는 한 톤 어둡게 보인다. WooaDev 색상 코드 변환 무료 사이트를 쓰면 이 어긋남을 30초 안에 확인할 수 있다. 문제는 도구가 없어서가 아니라, 어느 값이 진짜 원본인지 헷갈려서다. 포토샵 스포이드로 딴 값, 피그마에 적힌 값, 개발자가 하드코딩한 값이 서로 다르면 결국 다시 시안을 열게 된다.

## 왜 변환 단계에서 값이 틀어지는가

색상 코드는 같은 색을 여러 언어로 부르는 이름표일 뿐이다. HEX는 16진수, RGB는 10진수, HSL은 색상·채도·밝기 조합이다. 손으로 계산하면 반올림 오차가 쌓이고, 알파값이 붙으면 8자리 HEX와 RGBA 표기가 갈린다. 여기서 한 단계가 빠지면 최종 렌더링 색이 달라진다.

## WooaDev로 변환하는 순서

### 1단계: 원본 값 붙여넣기

[WooaDev 무료로 사용하기](https://wooadev.wooahouse.com)에 접속해 변환할 색상 코드를 입력란에 넣는다. #RRGGBB, rgb(0,0,0), hsl(0,0%,0%) 형식을 가리지 않고 받아준다. 복사한 값에 공백이나 세미콜론이 섞여 있어도 자동으로 정리된다.

### 2단계: 출력 형식 선택

HEX, RGB, HSL 중 필요한 표기를 고른다. CSS 변수용이면 HEX, 캔버스나 차트 라이브러리용이면 RGB가 편하다. 알파값이 필요하면 투명도 항목을 함께 조정한다.

### 3단계: 결과 복사 후 원본과 대조

변환된 값을 복사해 실제 화면에 적용하고, 원본과 나란히 놓고 비교한다. 이 대조 과정을 건너뛰면 브라우저 색상 프로필 차이를 코드 오류로 착각하게 된다.

### 4단계: 팔레트 단위로 정리

비슷한 색이 여러 개면 하나씩 변환하지 말고 묶어서 관리한다. 같은 계열 값이 HEX와 RGB로 뒤섞여 있으면 나중에 일괄 수정이 불가능해진다.

## 변환 전 확인할 것

- 모니터 색상 프로필이 sRGB인지 확인한다. Adobe RGB로 설정돼 있으면 같은 코드도 다르게 보인다.
- 브라우저 확대 비율이 100%인지 본다. 확대 상태에서는 서브픽셀 렌더링 때문에 미세하게 달라 보인다.
- 알파값이 있는 색은 배경색 위에서 확인한다. 투명도는 배경에 따라 체감 색이 바뀐다.
- 변환 결과를 눈으로만 판단하지 말고 값 자체를 비교한다.
