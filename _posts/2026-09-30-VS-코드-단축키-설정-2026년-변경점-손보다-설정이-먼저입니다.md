## 키보드만 붙잡고 있던 30분

VS 코드 단축키 설정을 제대로 안 해두면 같은 동작을 매번 마우스로 찾게 됩니다. 파일 탐색기 열고, 분할 창 만들고, 터미널 띄우는 데만 하루 수십 번씩 클릭이 쌓이죠. 문제는 "단축키 바꾸는 법"을 검색해서 나온 옛날 글대로 따라 했는데도 안 먹힌다는 겁니다.

## 왜 따라 해도 안 될까

대부분 세 가지 중 하나에 걸립니다. 첫째, keybindings.json에 넣은 키 조합이 이미 다른 기본 명령과 겹칩니다. 둘째, `when` 조건을 안 써서 특정 상황(예: 에디터 포커스 시)에서만 동작해야 할 키가 전역을 덮어씁니다. 셋째, 확장 프로그램이 나중에 로드되면서 사용자가 지정한 규칙을 밀어냅니다. 즉 키를 몰라서가 아니라 규칙의 우선순위를 몰라서 생기는 문제입니다.

## 설정을 눈으로 확인하는 도구

이럴 때 [WooaVS 무료로 사용하기](https://vskit.wooahouse.com)를 켜두면 정리가 빠릅니다. 이 사이트는 VS 코드 관련 설정과 키맵 정보를 한 화면에서 확인하도록 돕는 참고용 도구 모음입니다. 브라우저 탭 하나 띄워두고 keybindings.json을 옆에 놓고 대조하는 식으로 쓰면, 기억에 의존하지 않고 실제 키 조합을 눈으로 비교할 수 있습니다.

### keybindings.json 기본 골격

```json
[
  {
    "key": "ctrl+alt+t",
    "command": "workbench.action.terminal.toggleTerminal",
    "when": "editorTextFocus"
  }
]
```

여기서 `when`을 빼면 터미널 안에서도 같은 키가 먹혀 충돌합니다. `editorTextFocus`를 붙이는 순간 "코드를 편집할 때만"으로 범위가 좁혀집니다.

### 충돌을 찾는 순서

1. 명령 팔레트(Ctrl+Shift+P)에서 "키보드 바로 가기 문제 해결" 실행
2. 원하는 키를 그대로 눌러 어떤 규칙이 잡히는지 확인
3. 가장 위에 뜬 규칙이 실제로 실행되는 규칙이므로, 그것을 수정하거나 `when`으로 범위를 좁힘
4. 확장 프로그램이 원인이면 해당 확장의 기본 키를 비활성화

### 자주 쓰는 조합 정리

- 분할 편집: Ctrl+\\ (백슬래시)
- 사이드바 토글: Ctrl+B
- 빠른 파일 열기: Ctrl+P
- 심볼 이동: Ctrl+Shift+O
- 줄 삭제: Ctrl+Shift+K

이 중 하나라도 마우스로 하고 있었다면 그게 우선순위입니다. 키맵을 회사 동료와 맞춰야 한다면 설정 동기화 기능으로 keybindings.json만 따로 배포하는 편이 안전합니다.

## 실제로 써본 뒤 달라진 점

처음에는 "굳이 사이트까지 띄우나" 싶었습니다. 그런데 확장을 여러 개 깔고 나서부터는 달랐습니다. 예전에는 키가 안 먹으면 확장을 하나씩 꺼보며 원인을 찾느라 10분씩 날렸는데, 이제는 문제 해결 화면에서 잡히는 규칙을 먼저 보고 `when` 조건만 손봅니다. 설정 파일을 직접 편집하는 부담도 줄었습니다. 무엇보다 "왜 안 되지"에서 "이 규칙이 이기고 있구나"로 사고 방식이 바뀐 게 큽니다.

## 마무리

VS 코드 단축키 설정은 키를 외우는 일이 아니라 규칙의 우선순위를 다루는 일입니다. keybindings.json에 `when`을 붙이고, 충돌이 나면 문제 해결 화면부터 여는 습관만 들여도 같은 30분을 다시 쓰지 않습니다. 키맵 정보를 대조하며 정리하고 싶다면 [WooaVS](https://vskit.wooahouse.com)를 참고용으로 함께 열어두세요.
