## 메일 서명 아이콘이 깨지던 날

WooaDev 이미지 Base64 변환 방법을 찾게 된 계기는 사소했습니다. 회사 메일 서명에 넣은 작은 로고가 수신자 쪽에서 자꾸 엑스박스로 뜨는 문제였습니다. 원인은 간단했습니다. 이미지 파일을 외부 경로로 참조했기 때문입니다.

### 왜 이미지가 안 보였을까

메일 클라이언트는 보안상 외부 이미지 로딩을 기본 차단합니다. 상대방이 "이미지 표시" 버튼을 누르지 않으면 로고는 영영 보이지 않습니다. 웹페이지도 비슷합니다. 이미지 파일 경로가 한 칸만 틀려도, 서버에서 파일이 지워져도, 배포 폴더가 바뀌어도 이미지는 조용히 사라집니다. 이 문제를 우회하는 오래된 방법이 바로 Base64 인코딩입니다. 이미지를 문자 덩어리로 바꿔 HTML 안에 통째로 심어버리는 방식입니다.

## Base64 인코딩 vs 외부 파일, 뭐가 다른가

두 방식은 "이미지를 어디에 두느냐"만 다릅니다. 결과물은 똑같이 화면에 뜨지만 대가가 정반대입니다.

### 외부 파일 참조 방식

이미지를 별도 파일로 두고 `<img src="logo.png">`처럼 경로만 가리킵니다. 장점은 명확합니다. 용량이 늘지 않고, 브라우저가 이미지를 따로 캐싱해서 두 번째 방문부터는 로딩이 빠릅니다. 단점은 요청 한 번이 더 발생하고, 경로가 깨지면 그대로 실종된다는 점입니다.

### Base64 인라인 방식

이미지 자체를 문자열로 변환해 `src`에 직접 넣습니다. HTML 파일 하나만 있으면 이미지가 어디서든 살아 있습니다. 파일 요청이 0회라 초기 렌더링이 미세하게 빨라지는 경우도 있습니다. 대신 원본보다 용량이 약 33% 늘어나고, HTML 파일 자체가 무거워지면 캐싱 이점이 사라집니다. 작은 아이콘 몇 개에는 유리하지만, 고해상도 사진에는 손해입니다.

## WooaDev에서 변환하는 순서

[WooaDev 무료로 사용하기](https://wooadev.wooahouse.com)에 접속하면 별도 회원가입 없이 바로 쓸 수 있습니다.

### 1단계 — 이미지 올리기

변환 영역에 PNG, JPG, SVG, GIF 파일을 끌어다 놓거나 선택합니다. 파일은 서버로 가지 않고 브라우저 메모리에서만 읽힙니다.

### 2단계 — 문자열 확인

잠시 뒤 `data:image/png;base64,iVBORw0KGgo...` 형태의 긴 문자열이 나옵니다. 앞부분의 `data:image/확장자;base64,` 접두사까지 함께 복사하는 게 핵심입니다. 이걸 빼먹으면 이미지가 뜨지 않습니다.

### 3단계 — 원하는 위치에 붙여넣기

HTML이면 `<img src="여기">`, CSS라면 `background-image: url("여기")`에 넣으면 끝입니다. 반대로 Base64 문자열을 다시 이미지 파일로 되돌리는 디코딩도 같은 화면에서 처리됩니다.

## 실제로 써보니
