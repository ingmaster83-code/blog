## 주요 기능 한눈에 보기

### 1. 실제 MIME 타입 판별

파일 내부의 매직 넘버(magic number)를 읽어 진짜 형식을 확인합니다. `.jpg`인데 실제로는 WebP인 파일, `.txt`인데 UTF-16 BOM이 붙은 파일 같은 케이스를 정확히 잡아냅니다.

### 2. 확장자와의 불일치 경고

파일 이름의 확장자와 판별된 MIME 타입이 다르면 시각적으로 표시해줍니다. "왜 이 파일만 업로드가 안 되지?"라는 질문의 답이 대개 여기 있습니다.

### 3. 복사 가능한 Content-Type 문자열

`image/png`, `application/pdf`, `text/csv; charset=utf-8`처럼 헤더에 그대로 넣을 수 있는 형식으로 결과를 제공합니다. 서버 응답 헤더 설정이나 fetch 요청에 바로 붙여넣을 수 있습니다.

### 4. 여러 파일 동시 검사

드래그로 여러 개를 한 번에 넣으면 목록으로 비교됩니다. 확장자만 다르고 내용은 같은 중복 파일을 찾을 때도 유용합니다.

## 실무에서 바로 쓰는 활용 팁

### 업로드 검증 로직 디버깅

프론트엔드에서 `file.type`을 검사해 통과시켰는데 서버가 거부한다면, 두 값이 다를 가능성이 큽니다. 브라우저의 `file.type`은 확장자 기반 추정값이고, 서버가 보는 값은 실제 바이트 기반입니다. WooaDev로 실제 값을 먼저 확인한 뒤 허용 목록을 맞추면 왕복 수정이 줄어듭니다.

### API 응답 헤더 점검

CSV를 내려주는데 브라우저가 다운로드 대신 텍스트로 열어버린다면 Content-Type이 `text/plain`으로 잡혀 있을 수 있습니다. `text/csv; charset=utf-8`로 지정하면 엑셀에서 한글 깨짐 없이 열립니다. 인코딩 파라미터까지 함께 확인하는 습관이 중요합니다.

### 정적 파일 서버 설정 검증

Nginx나 CDN에서 `.woff2`, `.webp`, `.avif` 같은 최신 확장자의 MIME 매핑이 빠져 있으면 브라우저가 파일을 무시합니다. 배포 전에 실제 파일의 타입을 뽑아 서버 설정과 대조해두면 장애를 미리 막을 수 있습니다.

### 파일 형식 변환 전 원본 확인

이미지 변환 도구에 넣기 전에 원본이 정말 JPEG인지 확인하세요. 확장자만 믿고 변환하면 알파 채널이 날아가거나 색이 틀어지는 경우가 생깁니다. 원본 타입을 먼저 아는 것이 변환 품질을 지키는 첫 단계입니다.
