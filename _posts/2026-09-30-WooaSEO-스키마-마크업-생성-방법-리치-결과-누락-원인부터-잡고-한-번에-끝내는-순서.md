## 스키마 넣었다고 다 끝난 줄 알았던 이야기

WooaSEO 스키마 마크업 생성 방법을 검색하는 사람 대부분은 이미 한 번 실패를 겪은 경우가 많습니다. 코드를 붙였는데 서치콘솔에는 빨간 경고가 뜨고, 리치 결과 미리보기는 텅 비어 있고, 며칠 뒤 확인해도 검색 결과에 별점이나 FAQ 펼침이 나타나지 않는 상황 말입니다. 문제는 대부분 코드 자체가 아니라 "어디에, 무엇을, 어떤 순서로" 넣었는가에서 갈립니다.

이 글에서는 실패 지점을 먼저 짚고, 그다음 [WooaSEO 무료로 사용하기](https://wooaseo.wooahouse.com)로 넘어가 실제 생성 순서를 정리합니다. 구조화 데이터(Structured Data)는 한 번 감을 잡으면 이후 모든 글에 재사용할 수 있는 자산이 됩니다.

## 리치 결과가 누락되는 흔한 원인 4가지

### 1. 필수 속성을 빼먹은 경우

Article 스키마라면 headline, image, datePublished, author가 필수에 가깝습니다. 하나라도 비면 구글은 해당 항목 전체를 무시합니다. 특히 datePublished를 "2026-01-05" 형식이 아닌 "2026년 1월 5일"로 적어 넣는 실수가 잦습니다.

### 2. JSON-LD 위치를 잘못 잡은 경우

JSON-LD는 `<head>` 또는 `<body>` 끝에 `<script type="application/ld+json">` 블록으로 들어가야 합니다. 위지윅 편집기 본문 중간에 붙여 넣으면 테마가 태그를 이스케이프 처리하면서 코드가 그대로 노출됩니다.

### 3. 페이지 유형과 스키마 유형이 어긋난 경우

블로그 글에 Product 스키마를 넣거나, FAQ가 없는 페이지에 FAQPage를 넣으면 리치 결과 대상에서 제외됩니다. 페이지의 실제 성격과 스키마 타입이 일치해야 합니다.

### 4. 중복 선언으로 충돌한 경우

SEO 플러그인이 자동 생성한 스키마와 직접 넣은 스키마가 동시에 존재하면 구글이 어느 쪽을 신뢰할지 판단하지 못합니다. 한 페이지에 같은 타입은 하나만 두는 것이 안전합니다.

## WooaSEO로 스키마 마크업 만드는 순서

### 1단계: 페이지 유형 먼저 정하기

글, 상품, FAQ, HowTo, 리뷰 중 무엇인지 먼저 확정합니다. 타입이 정해져야 필요한 속성 목록이 자동으로 좁혀집니다.

### 2단계: 필수 값 채우기

제목, 대표 이미지 URL, 작성일, 수정일, 작성자명을 입력합니다. 이미지 URL은 반드시 실제 접근 가능한 절대 경로여야 하며, 상대 경로를 넣으면 검증에서 걸립니다.

### 3단계: 생성된 JSON-LD 복사

도구가 뽑아준 코드를 그대로 복사합니다. 이때 따옴표나 쉼표를 임의로 수정하지 않는 것이 중요합니다. JSON은 작은따옴표 하나만 바뀌어도 전체 파싱이 실패합니다.

### 4단계: 서치콘솔 리치 결과 테스트로 검증

URL 검사 도구에 페이지 주소를 넣고 "리치 결과 테스트"를 실행합니다. 감지된 항목과 누락된 항목이 목록으로 나오므로, 누락 항목만 채워 다시 검증하면 됩니다.

### 5단계: 색인 재요청

수정 후에는 반드시 색인 재요청을 걸어야 반영 속도가 빨라집니다. 반영까지는 보통 며칠에서 2주 정도 걸립니다.

## 실전에서 자주 쓰는 활용 팁

- 본문에 FAQ가 2개 이상 있으면 FAQPage를 별도로 추가하는 것이 펼침 노출에 유리합니다.
- 수정일(dateModified)을 실제로 갱신하면 재크롤링 주기가 짧아지는 경향이 있습니다.
- 하나의 페이지에 Article과 BreadcrumbList를 함께 넣는 것은 충돌이 아니라 보완 관계입니다.
- 스키마 검증은 배포 직후, 그리고 테마 업데이트 후 두 번 하는 습관이 안전합니다.
- 리치 결과는 노출 형태를 바꿀 뿐 순위를 직접 올리지는 않으므로, 본문 품질 작업과 병행해야 효과가 납니다.
