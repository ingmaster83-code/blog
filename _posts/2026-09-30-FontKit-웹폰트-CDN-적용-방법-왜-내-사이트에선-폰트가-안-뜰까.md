## 폰트 하나 바꿨다고 사이트가 멈칫한 이유

FontKit 웹폰트 CDN 적용 방법을 찾고 있었다면, 십중팔구 비슷한 상황일 겁니다. 분명히 `@font-face`도 넣었고 폰트 파일도 서버에 올렸는데, 새로고침하면 첫 1~2초 동안 글자가 안 보이거나 엉뚱한 기본 폰트로 반짝이는 현상. 저는 이걸 세 번 겪고 나서야 원인을 정리했습니다. 폰트 파일 자체가 무겁거나, 경로가 어긋났거나, 브라우저별로 요구하는 포맷이 달랐던 겁니다.

이 글에서는 그 세 가지를 한 번에 정리해주는 도구를 먼저 소개하고, 실제로 제 사이트에 적용하면서 겪은 순서를 그대로 공유합니다.

## FontKit, 어떤 도구인가

[FontKit](https://fontkit.wooahouse.com)는 폰트 파일을 웹에 바로 올릴 수 있는 형태로 변환하고, CSS 코드까지 함께 뽑아주는 웹 기반 도구입니다. 설치가 필요 없고 브라우저에서 열면 끝입니다. 처음 들어갔을 때 가장 반가웠던 건 별도 회원가입이나 파일 업로드 절차 없이 바로 폰트를 끌어다 놓을 수 있다는 점이었습니다.

주요 기능을 정리하면 이렇습니다.

### 1. 포맷 변환과 경량화

TTF나 OTF를 woff2, woff로 바꿔줍니다. 웹폰트 CDN을 직접 운영할 때 ttf를 그대로 올리면 용량이 몇 배로 불어나는데, woff2는 같은 글자를 절반 이하 크기로 압축합니다. 실제로 제가 쓰던 명조 계열 폰트 하나가 4.2MB에서 1.1MB로 줄었습니다.

### 2. 서브셋 추출

한글 폰트는 완성형 전체를 담으면 기본 2MB를 넘깁니다. FontKit은 실제로 쓰는 글자만 골라내는 서브셋 기능을 제공해서, 한 페이지 분량 텍스트 기준 100KB 안쪽으로 떨어뜨릴 수 있습니다. 이게 체감상 가장 큰 차이를 만듭니다.

### 3. CSS 코드 자동 생성

변환 결과와 함께 `@font-face` 선언문이 나옵니다. `font-display: swap` 옵션까지 기본으로 들어가 있어서, 폰트가 로딩되는 동안에도 텍스트가 먼저 보입니다. 이 한 줄이 없어서 첫 화면이 하얗게 비어 보였던 거였습니다.

## 실제 적용 순서

제가 사이트에 반영한 절차는 다음과 같습니다.

### 1단계: 폰트 파일 준비

가지고 있던 TTF 파일을 그대로 넣었습니다. 라이선스 확인은 먼저 하세요. 상업용 사이트라면 배포 허용 범위를 꼭 봐야 합니다.

### 2단계: 변환 및 서브셋 설정

한글 사용 빈도 기준으로 서브셋을 돌렸습니다. 여기서 주의할 점은, 나중에 추가할 콘텐츠에 없는 글자가 들어가면 그 부분만 다른 폰트로 표시된다는 겁니다. 저는 여유 있게 자주 쓰는 조합까지 포함시켰습니다.

### 3단계: CSS 붙여넣기

생성된 코드를 스타일시트 최상단에 넣었습니다. `font-family` 이름을 기존 CSS 변수와 맞춰주는 걸 잊지 마세요. 이름이 어긋나면 폰트를 불러왔는데도 적용이 안 된 것처럼 보입니다.

### 4단계: 캐시 확인

브라우저 캐시 때문에 새 폰트가 안 보이는 경우가 많습니다. 시크릿 창에서 먼저 확인하고, 정상이면 캐시 헤더를 조정합니다.

## 써보고 남은 것

솔직히 말하면, 예전에는 폰트 하나 바꾸는 데 반나절이 걸렸습니다. 변환 사이트 하나, 압축 사이트 하나, CSS 작성은 손으로. FontKit은 그 세 단계를 한 화면에 묶어놨습니다. 적용 자체는 5분이면 끝났고, 남은 시간은 폰트 조합을 고르는 데 썼습니다.

아쉬운 점도 있습니다. 폰트 패밀리를 여러 개 한꺼번에 관리하는 기능은 아직 약해서, 서체가 많아지면 개별로 작업해야 합니다. 그래도 웹폰트 CDN 적용 방법을 처음 찾는 분이라면 이 정도면 충분합니다.
