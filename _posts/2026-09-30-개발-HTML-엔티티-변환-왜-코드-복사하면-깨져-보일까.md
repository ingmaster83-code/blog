## 그 코드, 왜 붙여넣으면 사라질까

개발 HTML 엔티티 변환을 건너뛰고 코드를 그대로 에디터에 붙였다가 `<div>`가 통째로 사라진 경험, 한 번쯤 있을 것이다. 미리보기에는 빈 줄만 남고 태그는 어디에도 없다. 브라우저가 그걸 "설명할 코드"가 아니라 "실행할 태그"로 읽었기 때문이다.

## 주요 기능 훑어보기

### 실시간 변환과 역변환

텍스트를 넣는 순간 `<`, `>`, `&`, `"`, `'`가 각각 엔티티로 바뀐다. 반대 방향도 된다. 이미 엔티티로 뒤덮인 코드를 원래 기호로 되돌리는 디코딩이 한 버튼에 붙어 있어서, 남이 준 스니펫을 분석할 때도 왕복이 빠르다.

### 상황별 변환 범위 선택

HTML 속성값 안에서는 따옴표까지 막아야 하고, 일반 텍스트 노드에서는 꺾쇠만 처리해도 충분하다. 상황에 따라 변환 대상을 좁힐 수 있어서 결과물이 불필요하게 지저분해지지 않는다.

### 코드 블록·인라인 코드 대응

마크다운으로 기술 글을 쓸 때 인라인 코드와 펜스 블록을 구분해서 처리하면 렌더링이 훨씬 깔끔해진다. 백틱 안에 들어갈 내용만 골라 변환하는 흐름이 자연스럽다.

## 실무에서 바로 쓰는 팁

### 이중 변환 함정 피하기

`&lt;`를 다시 변환하면 `&amp;lt;`가 된다. 엔티티 표기를 예시로 보여주는 글을 쓸 때 이 실수가 자주 나온다. 변환 전에 원문에 `&`가 이미 있는지 먼저 확인하는 습관을 들이면 좋다.

### 사용자 입력값은 무조건 변환

댓글이나 폼 입력을 그대로 화면에 출력하는 코드를 짤 때, 변환을 빼먹으면 그대로 XSS 구멍이 된다. 서버 사이드 이스케이프와 별개로, 프런트에서 미리 눈으로 확인하는 용도로도 쓸만하다.

### XML·JSON 안에 HTML 넣을 때

API 응답에 HTML 조각을 담아 보내야 할 때, 따옴표와 앰퍼샌드가 그대로 있으면 파서가 먼저 죽는다. 전송 전에 한 번 통과시키는 것만으로 디버깅 시간이 크게 줄어든다.

### 복사 전 원본 백업

디코딩은 편하지만 되돌리기가 애매할 때가 있다. 원문을 메모장에 한 번 붙여두고 변환하는 편이 안전하다.
